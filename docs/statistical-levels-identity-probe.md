# Statistical Levels identity probe

`PROBE_IDENTITY` is a separate non-release operation in `.github/workflows/statistical-levels-release.yml` on `vercel-deployment`. It accepts only `probe_git_sha` and `probe_deployment_id`; the existing release inputs must be empty. No URL, role, project, service endpoint or Lambda name is accepted from the operator.

The probe resolves the immutable Preview using public GitHub metadata from the fixed Vercel integration. It selects the latest commit status for the supplied deployment ID, then requires the latest corresponding Preview deployment status to match the SHA, trusted creator, timestamp and exact origin links. A later Production deployment cannot replace the chosen Preview. No `deployments: read` permission or GitHub token is needed for these public reads.

Execution source and fixture source are separate checkouts. The workflow verifies its frozen helper hashes before running helpers, independently checks its GitHub execution identity and fixture ancestry, and verifies the fixture's pinned source files, 81 snapshots, provenance and 87-capability ledger. A probe records the fixture's authority as QA evidence; it never selects authority for publication. ADOPT and PROMOTE retain their existing validation, including PROMOTE's future-authority requirement and their unchanged controller request schemas.

Protected QA requests a short-lived GitHub OIDC token for `https://github.com/luiguiHerrera`. The token is held in memory and attached only to the verified Preview origin using `x-vercel-trusted-oidc-idp-token`. Cross-origin redirects are refused; bypass secrets, Vercel administrative tokens and Founder browser sessions are not used.

The direct `identity-probe` job has no GitHub Actions `environment` and no reusable-workflow boundary. Its Vercel and AWS tokens must both have the exact branch subject `repo:luiguiHerrera/Luiguiherrera-web:ref:refs/heads/vercel-deployment`. Vercel's target environment `Preview` does not create a GitHub job environment. Unexpected token `environment` remains forbidden. Exact issuer, audience, repository and immutable IDs, ref, caller workflow ref/SHA, execution SHA, workflow name, event, run ID/attempt, RS256 signature, key and time checks remain mandatory.

The current security policy is `JOB_WORKFLOW_IDENTITY_MUST_MATCH_EXACT_JOB_DEFINITION`. Each OIDC-validation step receives only four explicit native values: `job.workflow_ref`, `job.workflow_sha`, `job.workflow_repository` and `job.workflow_file_path`. They are passed at `steps.env`, where GitHub permits the job context; complete contexts are never serialized. The native job ref/SHA/repository must equal the independently qualified caller `GITHUB_WORKFLOW_REF`, `GITHUB_WORKFLOW_SHA` and `GITHUB_REPOSITORY`, and its path must equal `.github/workflows/statistical-levels-release.yml`. The caller SHA must also equal `GITHUB_SHA`. Both token `job_workflow_ref` and `job_workflow_sha` must be present and equal those exact native job values. Missing or mismatched claims fail with separate codes. Any native job/caller divergence fails as `UNEXPECTED_REUSABLE_OR_ALTERNATE_JOB_WORKFLOW_IDENTITY`; arbitrary reusable workflows are not accepted. See GitHub's [job context](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#job-context), [context availability](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#context-availability) and [September 3, 2026 updates](https://github.blog/changelog/2026-09-03-github-actions-early-september-2026-updates/).

Run `34477381010` observed a signed token with no `environment`, present `job_workflow_ref` and `job_workflow_sha`, and passing caller identity checks. It failed with `UNEXPECTED_JOB_WORKFLOW_REF` before any Preview HTTP. This disproves absence as a valid requirement for the observed direct job. Presence alone does not establish reusable-workflow execution. That run's exact two job workflow claim values are `NOT_RECOVERABLE_FROM_SANITIZED_EVIDENCE`; this repair does not invent them or infer them from the caller claims. Neither this run nor `34466337923` established a Trusted Sources failure. Live Trusted Sources and AWS OIDC certification remain pending. The separate probe verifier leaves the existing ADOPT/PROMOTE validator unchanged.

After QA succeeds, the existing pinned AWS credential action assumes only the fixed `LuiguiHerreraStatisticalLevelsReleaseInvoker` role. The probe session explicitly denies every AWS action except `sts:GetCallerIdentity`; that identity read does not require an IAM allow. The only AWS subprocess is a fixed STS identity call, with local credential files and endpoint overrides excluded and retries disabled. Its account, role and run-specific session must match; only a redacted proof is recorded. The probe contains no controller invocation path. See [AWS GetCallerIdentity](https://docs.aws.amazon.com/STS/latest/APIReference/API_GetCallerIdentity.html) and [Deny with NotAction](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_notaction.html).

One seven-day artifact, `statistical-levels-identity-probe-evidence`, contains exactly:

- `probe-summary.json`
- `trusted-sources-qa.json`
- `application-network-summary.json`
- `aws-oidc-summary.json`
- `qa-attestation.json`
- `evidence-sha256.json`

The artifact preserves the complete sanitized network event ledger and separate RSC/platform accounting. It excludes screenshots, headers, cookies, credentials, JWTs and credential-bearing URLs. Its hash manifest covers the other five exact files. Failed QA can retain a sanitized failure bundle; it cannot proceed to AWS. The finalizer rechecks source integrity, writes a complete bundle atomically and signals readiness only afterward. An integrity failure cannot execute an always-run helper or publish an unverified bundle.

Each token validation records a strict version 3 diagnostic containing booleans, classifications, a fixed error code and bounded, syntax-validated non-secret workflow identity metadata. It retains the exact safe token job workflow ref/SHA, native runtime ref/SHA/repository/path and direct-job comparison results; malformed or credential-shaped values are not reflected. Claims are evaluated only after signature verification; an unverifiable token yields no claim metadata. The private journal never contains the JWT, signature, authorization header or credentials and is not uploaded. Validated records are included in the existing Trusted Sources and AWS files; those wrappers and the probe summary use schema version 3. Controller and QA attestation schemas are unchanged. The artifact binds recorded caller SHA to its own execution context. Successful QA and AWS evidence require passing diagnostics for their respective audiences. A rejected initial token with no HTTP evidence yields `http_access_through_trusted_source=NOT_ATTEMPTED`; failures after initial validation yield `NOT_CERTIFIED`, never an inferred Vercel denial. Any failed OIDC gate keeps the overall probe failed, including an AWS preflight failure before assumption.

The package records the upstream source, patch, toolchain and binary hashes plus compatibility and negative tests.

The shared read-only browser and QA runner bodies are extracted unchanged. Release operation selection, temporal validation, controller payload construction, invocation code, publication lineage, authority policy, raw infrastructure and updater cron are unchanged.
